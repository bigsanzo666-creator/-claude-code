## 만들 것

`packages/manseryeok/` — 의존성 없는 순수 TypeScript 모듈.

```ts
type YajaMode = 'yaja' | 'joja' | 'midnight';  // 야자시 / 조자시 / 현대식 00시 기준

interface BirthInput {
  date: string;           // 'YYYY-MM-DD' (양력)
  time: string;           // 'HH:mm', 시간 모를 경우 null 허용
  longitude?: number;     // 기본 126.978 (서울)
  yajaMode?: YajaMode;    // 기본 'midnight'
  applyTrueSolarTime?: boolean;  // 기본 true
}

interface Pillar { stem: string; branch: string; }   // 천간/지지

interface Myeongsik {
  year: Pillar; month: Pillar; day: Pillar; hour: Pillar | null;
  meta: {
    correctedTime: string;      // 보정 후 시각
    solarTimeOffsetMin: number; // 진태양시 보정량 (분)
    dstApplied: boolean;        // 서머타임 적용 여부
    monthTermName: string;      // 적용된 절기명 (예: '입춘')
    monthTermEnteredAt: string; // 그 절기의 절입시각 (분 단위)
  };
}

function calculate(input: BirthInput): Myeongsik;
```

**핵심: `meta`를 반드시 반환할 것.** 계산 근거를 화면에 공개하는 것이 우리 차별점이다.
(경쟁 서비스들이 앱마다 명식이 달라 사용자 불만을 사고 있음)

## 구현 규칙 — 여기서 정확도가 갈린다

### 1. 절기 (가장 중요)
- **월주는 달력 월이 아니라 절기로 정한다.** 입춘부터 새 해, 각 절(節)부터 새 달.
- 24절기 중 월의 경계가 되는 것은 12개의 **절(節)**: 입춘·경칩·청명·입하·망종·소서·입추·백로·한로·입동·대설·소한
- 절입시각은 **분 단위**로 계산. 태양 황경이 315°(입춘), 345°(경칩), 15°(청명)… 가 되는 순간.
- **테이블로 박지 말 것.** VSOP87 축약판이나 Meeus 알고리즘으로 계산. 데이터가 짧아지고 정확도는 더 좋다.

### 2. 진태양시
- 표준시(UTC+9)는 동경 135° 기준. 서울(126.978°)은 약 **−32분** 보정.
- 공식: `(경도 − 135) × 4분`
- 균시차(equation of time)까지 반영할지는 옵션으로. 기본은 경도 보정만.

### 3. 서머타임
한국 시행 구간 (이 기간 출생자는 **−1시간**):
```
1948~1951, 1955~1960, 1987~1988
```
정확한 시작·종료 일시는 구현 시 확인해서 테이블로 둘 것. (이건 짧으니 테이블 OK)

### 4. 야자시 / 조자시
- `midnight` (기본): 00:00을 날짜 경계로. 23:00~23:59는 당일 일주, 자시.
- `yaja`: 23:00 이후는 **다음날 일주**로 넘김.
- `joja`: 23:00~23:59를 당일 일주 + 자시로 별도 표기.
- **정답이 없는 영역이므로 사용자가 고를 수 있게 하고, 기본값을 화면에 명시한다.**

### 5. 일주
- 60갑자 순환. 기준일을 하나 정하고 율리우스일수로 계산.
- **기준일 하나만 틀려도 모든 사용자의 명식이 어긋난다.** 검증 최우선 대상.
